# ru-check — вычитка

Проверь текст, указанный пользователем (аргумент команды, приложенный файл или последнее
сообщение, если ничего не указано).

## Порядок

1. Загрузи `SKILL.md` скилла ru-text и применимые файлы из `references/` по таблице
   маршрутизации. Для короткого текста хватает `typography.md` и `info-style.md`;
   для интерфейсных строк — `ux-writing.md`; для письма — `business-writing.md`.
2. Если текст похож на машинный, открой `references/addenda.md` (Neuroslop index) и оттуда
   иди в нужный файл: `addenda-rhythm.md`, `addenda-register.md`, `addenda-substance.md`.
3. Найди все нарушения. Плотность повышает тяжесть, но не заменяет находки: каждое
   вхождение — отдельной строкой со своей цитатой («Two rules that govern all the others»
   в `addenda.md`).
4. Не переписывай исходный файл. Верни исправленный текст и список правок.

## Формат ответа

```
## Исправленный текст

<текст целиком>

## Что изменено

| Было | Стало | Правило |
|---|---|---|
| … | … | R13 / AD-7 / §B info-style |

## Осталось на усмотрение автора

- … (спорные места, чужие цитаты, термины заказчика)
```

## Границы

- Чужие слова — цитаты, код, сторонние вставки — воспроизводятся как есть.
- Машиночитаемые строки (код, пути, URL, версии, флаги, данные для CSV/JSON/SQL) не трогать:
  см. «Do not touch (scope limits)» в `SKILL.md`.
- Если пользователь задал свой стиль, его просьба выше правил по умолчанию.
